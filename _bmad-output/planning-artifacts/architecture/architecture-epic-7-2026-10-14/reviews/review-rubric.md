# Rubric review — Epic 7 spine (AD-18 … AD-24)

## Verdict

**CONCERNS.** The spine is a genuinely good epic-altitude spine in its core: it correctly identifies that the only missing seam is the browser consumer, it ratifies rather than rewrites the accepted LOCAL core, and AD-18/AD-20/AD-21 are enforceable, falsifiable, and aimed at real divergence. It is not a PASS because of two critical gaps where the spine declares a boundary *closed* while leaving the thing that makes it closeable undefined, and because one whole dimension this altitude owns — the operational/environmental envelope of the browser shell (build, serving, CSP/headers, secure context, test substrate) — is silent in a spine whose entire job is to introduce a browser artifact into an existing AWS Amplify static pipeline.

It is not a FAIL: no AD-18..AD-24 rule contradicts an inherited AD-1..AD-17 rule, no AD contradicts the real code, and the four Story 7.1 acceptance criteria are each architecturally reachable. The findings below are closeable by editing the spine; none require reopening the parent.

## 1. Does it fix the real divergence points for the stories, and miss none?

Mostly yes, and the hit rate is high. The six divergence points that a browser-consumer slice actually creates are: who owns the reducer wrapper (AD-18), who writes the address (AD-19), where the digest comes from in a browser (AD-20), what data the browser is allowed to see (AD-21), where remaps come from (AD-22), and who owns teardown (AD-23). AD-24 adds the vocabulary seam. That is the correct set, and each one is traceable to a real artifact in the repo rather than to a hypothetical.

AD-20 is the strongest AD in the document. It is a real, verified hazard: [memory-snapshots.mjs:2](../../../../../src/adapters/memory-snapshots.mjs#L2) does `import { createHash } from 'node:crypto'` and line 6 exports `sha256Text`, and every current `SnapshotReader` construction site injects exactly that — [local-fixtures.mjs:13](../../../../../tests/helpers/local-fixtures.mjs#L13), [local-snapshot.test.mjs:61](../../../../../tests/local-snapshot.test.mjs#L61), [demo-local-core.mjs:10](../../../../../scripts/demo-local-core.mjs#L10). Meanwhile [snapshot-reader.mjs:6](../../../../../src/application/snapshot-reader.mjs#L6) already takes `digest` as a constructor port, so the rule is satisfiable with zero refactor. The AD prevents a real thing and costs nothing.

**F-1 — Missed divergence point: the shell's own composition root is unowned. Severity: medium.**
AD-18 names a single owner for the store wrapper, and AD-19/AD-20/AD-21/AD-23 all assign work to "o shell" as if the shell were a single unit. But the shell is the one unit this epic actually creates, and the spine never says it is singular. `src/ui/` in the Structural Seed at line 139 is a *directory*, not an owner. Two stories (7.1's search dialog, and a later Globo consumer) can each legitimately build their own composition root inside `src/ui/`, each injecting its own `digest`, its own fixture ports, its own history writer — every one of them individually compliant with AD-19 ("o shell é o único escritor") because each believes itself to be "o shell". AD-18 solves exactly this problem for the store and then does not generalize it to the shell. Fix: one sentence naming a single `src/ui/` composition module that constructs the store, the ports, and the address writer, with every other UI module receiving them by injection.

**F-2 — Missed divergence point: `select=` is named an alias of a canonical key that does not exist. Severity: high.**
AD-24 at line 108 lists `select=` among the legacy prototype forms to be translated at the edge, and implies `company=` is its canonical counterpart. Verified against the prototype: `select=` carries a *company id* at [prototype-artificial-analysis.html:1134](../../../../../_bmad-output/planning-artifacts/ux-designs/ux-LLMs-2026-10-09/mockups/prototype-artificial-analysis.html#L1134), so `select=` → `company=` is a defensible mapping. But the same line also reads `params.get('reader')` and uses `select=` as the *reader's* news id source, and line 1135 reads `pov=asia` to set camera. There is no canonical key for a reader target or a camera position: `explorationQuery` at [exploration-url.mjs:21-27](../../../../../src/domain/exploration-url.mjs#L21-L27) emits exactly four keys (`layers`, `base`, `tab`, `company`) and `parseExplorationUrl` at lines 4-20 reads exactly those four plus `view`. So AD-24 instructs implementers to translate `reader=` and `pov=` into a canonical vocabulary that has no slot for them. Two implementers will diverge predictably: one drops them (defensible — "o endereço serializado nunca emite alias legado"), one adds `reader=`/`pov=` to the canonical URL contract (also defensible — they are listed as things the edge must handle). This directly affects Story 7.1's third AC, which demands the URL "saneia valores desconhecidos para opções válidas". Fix: AD-24 must state explicitly that `reader=` and `pov=` have no canonical counterpart and are *discarded*, not translated — or defer them with a named owner.

**F-3 — Missed divergence point: `mode`/`theme` are preferences, not address state, and AD-24 blurs the two. Severity: medium.**
AD-24 line 108 lists `mode: dark|light` as canonical vocabulary and `mode=claro|escuro` as a legacy alias. But `mode` is a *persisted preference* in the real code — [exploration.mjs:9](../../../../../src/contracts/exploration.mjs#L9) puts `mode` in `PREFERENCE_KEYS`, and [exploration.mjs:187](../../../../../src/contracts/exploration.mjs#L187) restricts `sessionOverrides` to exactly `['layers','base','tab','companyId']`, so `mode` **cannot** be a URL override in the current state machine. The prototype does read it from the URL ([prototype-globe.html:518](../../../../../_bmad-output/planning-artifacts/ux-designs/ux-LLMs-2026-10-09/mockups/prototype-globe.html#L518) `pref('mode','mg-mode',...)`, which falls back from URL param to `localStorage`). An implementer following AD-24 literally will build `?mode=dark` handling; following AD-19's "hidratação grava apenas `sessionOverrides` e nunca persiste preferência" plus the contract, that URL must be *ignored*. These two readings produce incompatible address writers. Same hazard for `theme=` at [prototype-globe.html:517](../../../../../_bmad-output/planning-artifacts/ux-designs/ux-LLMs-2026-10-09/mockups/prototype-globe.html#L517), which AD-24 does not list at all. Fix: AD-24 should separate "canonical *state* vocabulary serialized into the address" from "canonical *preference* vocabulary that the address never carries", and say that preference-valued legacy params are dropped at the edge.

## 2. Is every AD's Rule enforceable, and does it prevent its stated divergence?

Enforceable and effective: AD-18 (checkable by `grep` for a second module holding exploration state, plus a test that `dispatch` returns effects and executes none), AD-20 (checkable by a module-graph assertion that no `src/ui/` import reaches `src/adapters/`; the repo already has a module walker in [check-local.mjs:3](../../../../../scripts/check-local.mjs#L3) that could carry it), AD-21 (checkable: the rule names the *exact* anti-pattern `authorizeRead: c => c === owner`, which is verbatim what [demo-local-core.mjs:7](../../../../../scripts/demo-local-core.mjs#L7) and [local-fixtures.mjs:12](../../../../../tests/helpers/local-fixtures.mjs#L12) do — naming the real line is what makes it enforceable).

**F-4 — AD-23 prescribes `LocalSearch.cancel()` as the disposal mechanism, but `cancel()` does not prevent publication after disposal. Severity: critical.**
AD-23's Rule at line 102 says: "Ao trocar instância de store ou perder permissão, o shell cancela as subscriptions, chama `LocalSearch.cancel()` e abandona operações em voo." Read the real `cancel()` at [local-search.mjs:33-36](../../../../../src/application/local-search.mjs#L33-L36): it sets `#generation = null` and publishes `idle`. Now read the in-flight guard it is supposed to arm — `#active()` at [local-search.mjs:25-27](../../../../../src/application/local-search.mjs#L25-L27) calls `this.#intentToken()`, which at lines 16-19 calls `requireSynchronous(this.#store.getState())` and `integer(state?.intentToken, ...)`. After the shell has disposed of the store instance, the awaited `#view.frame()` resumes at line 43, `#active()` runs, `getState()` is called on a store the shell has abandoned — and if that store was replaced or torn down, `integer()` *throws* ([primitives.mjs:25-27](../../../../../src/contracts/primitives.mjs#L25-L27) → `fail()` → `TypeError`). That throw lands in the `catch` at [local-search.mjs:47-51](../../../../../src/application/local-search.mjs#L47-L51), which calls `#active(operation)` again (throws again, now *outside* any try) or, if `getState()` still answers, publishes `unavailable` — i.e. a disposed search instance mutates `#current` after disposal and a renderer still subscribed to it observes a post-disposal state transition. `cancel()` nulls the generation but nothing *awaits* or *fences* the pending promise. This is exactly the divergence AD-23 claims to prevent ("subscription órfã manter renderer morto recebendo estado"), and the prescribed mechanism does not prevent it. It is critical because the spine presents it as closed: the rule names a concrete API as the answer, so an implementer will call it and believe the invariant holds. Fix: AD-23 must require the shell to hold the disposal *fence* itself — e.g. a disposed-flag the shell checks before routing any resolved result into a renderer or store — and must state that `LocalSearch.cancel()` is a courtesy, not a barrier. Note this is the same residual hazard already recorded as BH3 in [deferred-work.md:54-56](../../../../implementation-artifacts/deferred-work.md#L54-L56), which the spine does not cite.

**F-5 — AD-19's intent classification covers 6 of the 12 real intent types; the rest is silent, and the address writer is the one unit that must be total. Severity: high.**
AD-19 at line 78 classifies `company`, `tab`, `navigate`, and search-result selection as `pushState`, and `base`, `layers`, `preference` as `replaceState`. The executable intent vocabulary is [exploration.mjs:113](../../../../../src/contracts/exploration.mjs#L113): `hydrateUrl, preference, tab, base, company, panel, openNews, camera, callback, escape, advanceSnapshot, navigate` — twelve types. Unclassified: `panel`, `openNews`, `camera`, `escape`, `callback`, `advanceSnapshot`. Four of those six demonstrably change `effectiveState`-adjacent state that the four serialized keys *can* reflect: `openNews` at [exploration-state.mjs:99-101](../../../../../src/domain/exploration-state.mjs#L99-L101), and critically `advanceSnapshot` at [exploration-state.mjs:121-126](../../../../../src/domain/exploration-state.mjs#L121-L126) can set `companyId` to `null` — meaning a snapshot advance silently changes what `explorationQuery` would serialize. An implementer who treats "any state change → write the address" will push a history entry on every snapshot refresh (the exact "histórico inflado" divergence AD-19 names); an implementer who writes only on the seven listed intents will leave the address stale after `advanceSnapshot`, so a copied link reopens an entity the session no longer has. Both are literally compliant. Fix: AD-19 must be total over the intent vocabulary — classify each of the twelve as push / replace / no-write, or state a default rule ("any intent not listed does not write the address") plus the `advanceSnapshot` exception.

**F-6 — AD-22 mandates a manifest field without specifying its shape, while naming the shape that already exists in a *different* contract. Severity: critical.**
AD-22's Rule at line 96: "O Publicador declara os `companyRemaps` no manifesto da revisão; eles atravessam o frame de `LocalNewsView` e o consumidor apenas os repassa a `advanceSnapshot`. ... O contrato do manifesto precisa carregar esse campo, com fixtures válidas e inválidas nos dois lados, antes das stories consumidoras." Three concrete problems, all verifiable:
1. `assertManifest` at [snapshot.mjs:7-17](../../../../../src/contracts/snapshot.mjs#L7-L17) uses `object(value, ['schemaVersion','revision','curationRevision','publishedAt','slices'], 'Manifest')`, and `object()` at [primitives.mjs:4-14](../../../../../src/contracts/primitives.mjs#L4-L14) is **exact-key**: `if (keys.length !== fields.length ...) fail()`. Adding `companyRemaps` to the manifest is therefore a *breaking* change to `schemaVersion: 1`, which collides head-on with inherited AD-16's "Mudança incompatível exige nova versão/migração" and AD-2's "O Publisher é o único escritor do manifesto `schemaVersion: 1`". AD-22 does not say whether this is `schemaVersion: 2`, an optional field, or a sibling slice. Three implementers, three incompatible manifests.
2. The field shape is undefined in the manifest, while an *identically named* field already exists with a fixed shape in the intent contract — [exploration.mjs:138-141](../../../../../src/contracts/exploration.mjs#L138-L141) requires exactly `{fromCompanyId, toCompanyId}`. "Repassa a `advanceSnapshot`" implies the manifest shape equals the intent shape, but AD-22 never says so, and a Publicador who adds provenance (`evidence`, `decidedAt`) produces a manifest the consumer cannot forward without reshaping — which is precisely the "dois consumidores derivarem remaps diferentes" the AD claims to prevent.
3. The transport path "manifesto → frame de `LocalNewsView`" does not exist and the spine does not say who adds it. `LocalNewsView.#frame()` at [local-news-view.mjs:26-39](../../../../../src/application/local-news-view.mjs#L26-L39) builds its frame from four injected ports and returns `{data, now, hiddenNewsIds, dataRevision, feedbackRevision}` — the manifest is reachable only as `data.manifest.revision` at line 36, and `readSnapshot` returns the *merged* snapshot. `LocalSearch.select()` at [local-search.mjs:61-62](../../../../../src/application/local-search.mjs#L61-L62) hardcodes `companyRemaps:[]`. So AD-22 requires changes to a `src/application/` module and to a `src/contracts/` module, declares them mandatory "antes das stories consumidoras", and assigns neither an owner nor a shape. Critical for the same reason as F-4: the spine declares this seam closed. This is the open half of BH5 in [deferred-work.md:58-60](../../../../implementation-artifacts/deferred-work.md#L58-L60), also uncited.

**F-7 — AD-24 cites `parseExplorationUrl`'s `view=` handling as the model for the alias table, but that handling is case-sensitive and silently collapses unknown values; as a template it propagates a bug. Severity: medium.**
AD-24 line 108: "aliases legados traduzidos numa única tabela na borda de entrada, como `parseExplorationUrl` já faz com `view=`." Probed the real behavior at [exploration-url.mjs:15-16](../../../../../src/domain/exploration-url.mjs#L15-L16):

| URL | result |
| --- | --- |
| `?view=3D` | `{}` (correctly ignored) |
| `?view=3d` | `{"base":"MAPA"}` |
| `?view=sat` | `{"base":"MAPA"}` |
| `?view=mapa` | `{"base":"MAPA"}` |

The prototype emits **lowercase** (`data-v="3d"`, `data-v="sat"`, `data-v="mapa"` at [prototype-globe.html](../../../../../_bmad-output/planning-artifacts/ux-designs/ux-LLMs-2026-10-09/mockups/prototype-globe.html) and [prototype-artificial-analysis.html](../../../../../_bmad-output/planning-artifacts/ux-designs/ux-LLMs-2026-10-09/mockups/prototype-artificial-analysis.html)), so every real legacy link `?view=3d` is read as an *explicit base override to MAPA* rather than as "no base opinion" — the parent spine's Q11 at [parent:216](../../architecture-LLMs-2026-10-10/ARCHITECTURE-SPINE.md#L216) says `view=3D` must not choose a base, and the lowercase form violates that. `?view=sat` loses the user's SAT. Holding this up as the exemplar tells implementers to copy the case-sensitivity. Contrast `tab=globo`, which *does* resolve to `globe` ([exploration-url.mjs:17](../../../../../src/domain/exploration-url.mjs#L17)) — but only incidentally, via the sanitize-to-`'globe'` fallback, not via a translation table, so AD-24's claim that translation already happens in one place is not true of `tab` either. Fix: either make the citation precise ("extend `view=` handling to be case-insensitive and build the single table there") or drop the exemplar.

**F-8 — AD-18's reentrancy prohibition is stated as a store property but is violated by the accepted consumer, not by the store. Severity: medium.**
AD-18 line 72: "o store não chama nada que possa despachar durante um `dispatch`." Enforceable as written, and the reducer is pure. But the hazard AD-18 names in its Prevents clause — "handler de efeito despachar reentrantemente e corromper a sequência de `intentToken` que `LocalSearch` usa" — lives in `LocalSearch`, which *manually* compensates: [local-search.mjs:63](../../../../../src/application/local-search.mjs#L63) and [:71](../../../../../src/application/local-search.mjs#L71) do `operation.intentToken += 1` after each dispatch, with the comment at line 64 acknowledging "Uma subscription síncrona pode ter emitido nova intenção durante o dispatch." So the accepted code's correctness depends on *exactly one* token increment per dispatch and on no subscriber dispatching. AD-18 forbids the store from re-entering but says nothing about **subscribers**, which is where the real coupling is. A shell whose subscriber dispatches (e.g. a renderer that corrects `tab` on receipt) breaks `LocalSearch.select()` while complying with AD-18. Fix: extend the rule to subscribers — "nenhum subscriber despacha de forma síncrona durante a notificação" — and note the `+= 1` coupling as the reason.

## 3. Could anything under Deferred let two units diverge?

**F-9 — "Interface e acessibilidade (Q3)" defers the keyboard/focus envelope that Story 7.1's second AC requires, with no seam fixed in its place. Severity: high.**
Line 156 defers "foco, `Esc`, teclado, toque, ordem de Tab e a matriz de browser ... este spine só fixa o lifecycle que as sustenta (AD-23)." But Story 7.1 AC-2 at [epics.md:1633-1635](../../../epics.md#L1633-L1635) requires: "Popover/campo recebem foco, Esc segue a prioridade e uma intenção vencida não troca o destino atual." The `Esc` *priority* is not a UI detail — it is executable domain behavior, implemented at [exploration-state.mjs:102-107](../../../../../src/domain/exploration-state.mjs#L102-L107) as a strict ladder (reader-typing → reader → sidePanel → terminal-typing → terminal). The search dialog is a **new** focus surface that this ladder does not know about: the `escape` intent has no branch for it, and `sidePanel` is constrained to `[null,'queue','markets','reader']` at [exploration.mjs:209](../../../../../src/contracts/exploration.mjs#L209). So where does the search dialog sit in the ladder? Unit A handles `Esc` locally in the shell before dispatching (search closes first, always); Unit B dispatches `escape` and lets the reducer decide (search never closes while the reader is typing). Both comply with AD-23 and with the Q3 deferral; they ship incompatible `Esc` semantics — and the parent's AD-10 at [parent:100](../../architecture-LLMs-2026-10-10/ARCHITECTURE-SPINE.md#L100) already binds "`Esc` age no foco superior e completa digitação primeiro", so one of the two is also violating an inherited invariant. The seam (does the search dialog's `Esc` enter the domain ladder or not?) is architectural and belongs here. Fix: decide the single question "is the Busca dialog a member of the `escape` ladder?" and defer only the visual/a11y finishing.

**F-10 — "CR-02/CR-08, roundtrip de URL sem `company`" is deferred to "a story que introduzir links externos", which is 7.1 itself. Severity: medium.**
Line 155 reasons: "`explorationQuery` sempre emite as quatro chaves, então toda URL produzida pelo sistema carrega `company`" — verified true at [exploration-url.mjs:24-25](../../../../../src/domain/exploration-url.mjs#L24-L25), including the empty form `company=` which does force `companyId:null` (probed). Good reasoning. But the conclusion — defer the semantics of hand-edited/legacy addresses to a later story — collides with AD-24, which *requires* this epic to accept legacy prototype addresses (`select=`, `tab=globo`), and legacy prototype addresses by construction have **no** `company` key. So the epic mandates consuming exactly the class of URL whose semantics it defers. Two implementers: one treats a legacy URL's missing `company` as "no opinion, keep session" (matching CR-08's recorded behavior in [deferred-work.md:37](../../../../implementation-artifacts/deferred-work.md#L37)); the other normalizes legacy → canonical at the edge and emits `company=`, clearing the selection. Fix: state which one AD-24's translation table produces.

**F-11 — "Bundler e forma de servir módulos (Q9)" is deferred, but AD-20's enforcement and AD-21's packaging both depend on the answer. Severity: medium.**
Line 159 defers Q9 and asserts "AD-20 e AD-24 valem em qualquer escolha." AD-20's rule is *about* bundler behavior ("Prevents: um bundler arrastar `node:crypto` para o cliente") and AD-21's rule says fixtures are "empacotadas" — both are claims about a pipeline that does not exist: the only build is [build-ui-preview.mjs](../../../../../scripts/build-ui-preview.mjs), which `cp`s the mockups directory ([build-ui-preview.mjs:30-33](../../../../../scripts/build-ui-preview.mjs#L30-L33)) and emits no `.mjs` at all (`find` over the mockups tree returns zero `.mjs` files). The invariant "valem em qualquer escolha" is true but unenforceable until someone picks; meanwhile nothing in the spine says *who* adds the module-graph check that makes AD-20 falsifiable. Low-cost fix: require the AD-20 check as a repo-level assertion in `npm run check` (the walker at [check-local.mjs:3](../../../../../scripts/check-local.mjs#L3) already enumerates every `.mjs`), which is bundler-independent.

**F-12 — "CR-03, CR-04, CR-06, CR-07 permanecem `maybe-false`" is an accurate deferral; CR-05 is silently promoted without being named. Severity: low.**
Line 157 lists CR-03/04/06/07. AD-23's Prevents clause at line 101 is a verbatim restatement of CR-05 from [deferred-work.md:34](../../../../implementation-artifacts/deferred-work.md#L34) ("callback deliberadamente roteado de uma instância para outra com token/revisão iguais"), which is correct and good — but the spine never cites CR-05 by ID, so a reader reconciling the CR ledger against the spine will find CR-05 missing from both the Deferred list and the AD text. One ID citation closes it. Likewise CR-09 (warning cleared by base change, [deferred-work.md:38](../../../../implementation-artifacts/deferred-work.md#L38)) is neither decided nor deferred anywhere, though it is squarely a browser-consumer presentation question this epic introduces.

**F-13 — `crypto.subtle.digest` is named as a drop-in for the `digest` port, but the two have incompatible signatures and a secure-context precondition the spine does not state. Severity: high.**
AD-20 line 84: "o shell injeta um digest Web Crypto (`crypto.subtle.digest`) na porta `digest` que `SnapshotReader` já aguarda." The port's actual contract, at [snapshot-reader.mjs:14](../../../../../src/application/snapshot-reader.mjs#L14): `if (typeof bytes !== 'string' || await this.#digest(bytes) !== manifest.slices[slice].digest)` — the port takes a **string** and must return a **lowercase 64-char hex string**, because that is what `assertManifest` enforces at [snapshot.mjs:12](../../../../../src/contracts/snapshot.mjs#L12) (`if (!/^[a-f0-9]{64}$/.test(ref.digest)) fail('digest')`) and what [memory-snapshots.mjs:6](../../../../../src/adapters/memory-snapshots.mjs#L6) produces via `createHash('sha256').update(text).digest('hex')`. `crypto.subtle.digest` takes a **BufferSource** and resolves an **ArrayBuffer** ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest)). So the shell must supply an adapter that `TextEncoder`-encodes the input and hex-encodes the output — and the encoding choice (UTF-8, lowercase hex, no separators) is exactly the kind of detail two units get differently, producing `SNAPSHOT_DIGEST_INVALID` on one and not the other. Worse, the spine calls `crypto.subtle` an "API de plataforma, sem dependência" (line 127) without noting that `crypto.subtle` is **undefined outside a secure context** — fine on `https://irisglobal.com.br`, but it silently breaks any `http://` local preview, which is the development path this epic is about to create. Fix: AD-20 must specify the adapter contract (`string → UTF-8 bytes → SHA-256 → lowercase hex`) and record the secure-context precondition.

## 7. Does any new AD weaken or contradict an inherited one?

No direct contradiction. I checked each new AD against the seven inherited invariants the spine binds (and against AD-14, which it does not bind — see §8).

- **AD-18 vs AD-10** — strengthens. AD-10 says "um reducer é o único escritor semântico"; AD-18 adds that only one module may wrap it and that effects return to the caller. Consistent with [exploration-state.mjs:155](../../../../../src/domain/exploration-state.mjs#L155) returning `{state, effects}`.
- **AD-19 vs AD-10** — strengthens, and correctly restates AD-10's "Hidratação de URL não dispara persistência". It also correctly operationalizes the parent's Q11 resolution ([parent:216](../../architecture-LLMs-2026-10-10/ARCHITECTURE-SPINE.md#L216)) by serializing `base`.
- **AD-20 vs AD-2/AD-16** — compatible. The digest port substitution does not change the manifest format, so `schemaVersion: 1` integrity checking is preserved.
- **AD-21 vs AD-9** — this is the interesting one, and the spine handles it honestly. AD-9 ([parent:94](../../architecture-LLMs-2026-10-10/ARCHITECTURE-SPINE.md#L94)) requires server-side identity before serving assets or JSON and says "Config ausente nega acesso". A fixture-only static preview on Amplify serves assets with **no** identity check — which would be a flat AD-9 violation if the assets contained private data. AD-21 resolves it the only legitimate way: forbid private data on that path entirely, and escalate the reconciliation to Andre as Q12 (line 154). The Inherited table at line 50 explicitly flags "Limita o caminho de dados (ver AD-21, Q12)". **This is correct architecture, not a weakening** — and surfacing it as Q12 is exactly what an epic spine should do with an inherited invariant its environment cannot yet satisfy.
- **AD-22 vs AD-3** — strengthens AD-3's "merge exige decisão humana" by forbidding heuristic remap derivation. But see F-6: *implementing* it as written collides with AD-2 ("Publisher é o único escritor do manifesto `schemaVersion: 1`") and AD-16 ("Mudança incompatível exige nova versão/migração"), because the exact-key `object()` validator makes any manifest field addition breaking. That is a **latent** conflict created by under-specification, not by a contradictory rule.
- **AD-23 vs AD-10** — compatible; adds lifecycle AD-10 never covered.
- **AD-24 vs AD-10/AD-16** — strengthens AD-16's single-author rule and implements AD-10's "compatibilidade dos parâmetros legados é Q11". But note it **partially reopens** a resolved parent gate: Q11 ([parent:216](../../architecture-LLMs-2026-10-10/ARCHITECTURE-SPINE.md#L216)) already fixed `view=MAPA|SAT` / `view=3D` / `view=2D` semantics, and AD-24 restates them while adding five more aliases. Restating a resolved gate's conclusions is fine; the risk is drift if either document is edited. Worth a one-line pointer "AD-24 estende Q11 sem reabri-lo".

**F-16 — AD-24's canonical list omits `projection`, the one field the parent pins hardest. Severity: low.** AD-24 enumerates canonical vocabulary as "`tab: globe|models|news`, `mode: dark|light`, `company=`, `base=MAPA|SAT`" and lists `view=3d` as a legacy alias. The real state machine pins `projection: '3D'` as an invariant ([exploration.mjs:194](../../../../../src/contracts/exploration.mjs#L194) `oneOf(context.projection, ['3D'], 'projection')`), and AD-10/AD-17/Q10 all insist the Globe is permanently 3D. Saying so in AD-24 — "`projection` é canônico, imutável, e nunca serializado" — forecloses an implementer reintroducing `view=3d` as a *canonical* key on the grounds that the canonical list did not mention projection.

## 8. Is every dimension this altitude owns decided, deferred, or an open question?

Dimensions this spine owns and covers: state ownership (AD-18), addressing (AD-19), platform crypto (AD-20), data provenance/authorization posture (AD-21), entity reconciliation (AD-22), lifecycle (AD-23), vocabulary (AD-24), dependency direction and synchrony (Consistency Conventions), module placement (Structural Seed), capability mapping (Capability → Architecture Map). That is good coverage for an epic altitude, and the Deferred section explicitly routes chat/Histórico, bundler, UI/a11y, and the CR ledger elsewhere.

**F-17 — The operational/environmental envelope of the browser shell is a silent dimension. Severity: critical (as a rubric finding: a whole dimension this altitude owns is neither decided, deferred, nor made an open question).**

This epic's entire deliverable is *a new browser artifact in an existing deployment pipeline*, and the spine says nothing about that pipeline. The inherited invariant that governs it, **AD-14** ([parent:120-124](../../architecture-LLMs-2026-10-10/ARCHITECTURE-SPINE.md#L120-L124) — "local/test usam fixtures sintéticas; preview/prod têm bancos, objetos, segredos... isolados", "Não há deploy/cron/ativação paga automática por teste, build ou instalação"), is **not in the `binds:` list at line 11** and appears nowhere in the Inherited Invariants table — even though AD-21 is substantially an AD-14-shaped rule (fixtures only, no real data) and the spine's own Stack table cites `amplify.yml`. Concretely unaddressed:

1. **The build does not build the shell.** The only build is `npm run build:ui` → [build-ui-preview.mjs](../../../../../scripts/build-ui-preview.mjs), which copies the UX mockups directory into `dist/ui` ([lines 30-33](../../../../../scripts/build-ui-preview.mjs#L30-L33)) and exits. `find` over that mockups tree returns **zero** `.mjs` files. [amplify.yml:13](../../../../../amplify.yml#L13) then gates on `test -s dist/ui/index.html`. So the shell AD-18..AD-24 describe has no path into `dist/ui`, and the spine never says whether the shell replaces the prototype preview, ships beside it, or is served from somewhere else. Unit A extends `build-ui-preview.mjs`; Unit B adds a second script; Unit C introduces a bundler (and Q9 says that is undecided). All compliant.
2. **Headers/CSP are owned by files the spine never mentions.** [customHttp.yml](../../../../../customHttp.yml) sets `Cache-Control: no-store` for `/assets/cesium-config.json` and `Referrer-Policy: origin` for `/prototype-cesium*`, and `build-ui-preview.mjs:35` *also* writes a `_headers` file with the same two rules. Per [AWS's documentation](https://docs.aws.amazon.com/amplify/latest/userguide/setting-custom-headers.html), Amplify reads `customHttp.yml` at the repo root; a `_headers` file is a Netlify/Cloudflare convention, so one of those two mechanisms is inert on this host. A shell serving fixture JSON needs its own cache/CSP posture (AD-9's "Respostas privadas usam cache privado"), and nothing in the spine assigns it. Note the pattern `/prototype-cesium*` also would not match a new shell entry point.
3. **Secure context for `crypto.subtle`** — see F-13; this is an environmental precondition, not an API detail.
4. **No browser test substrate.** `grep` for `jsdom`/`happy-dom`/`document.`/`window.` across `src/`, `tests/`, `scripts/` → zero matches; the runner is `node --test` over `tests/*.test.mjs`. AD-23 mandates "Teste de disposal comprova isolamento entre instâncias antes de fechar a story" and AD-19 mandates `pushState`/`replaceState`/`popstate` behavior — none of which the current substrate can exercise. The spine does not say whether these are tested via injected fake `history`/`storage` ports (which would be the AD-20-consistent answer, and is cheap) or via a new browser harness (a new dependency, contradicting "Nenhum pacote novo é introduzido"). This is the mechanism that makes AD-19 and AD-23 falsifiable, so leaving it silent weakens both.
5. **Build-time secrets at the shell boundary.** `build-ui-preview.mjs` requires `CESIUM_ION_PUBLIC_TOKEN` and `CESIUM_APP_ORIGIN` and writes them into `dist/ui/assets/cesium-config.json` with mode `0o600` ([line 34](../../../../../scripts/build-ui-preview.mjs#L34)). AD-9 forbids secrets in "snapshots, bundles, URLs ou logs". A shell that ships beside this preview inherits that pattern; the spine does not say whether the shell may read that config, must not, or whether a fixture-only shell needs any token at all.

None of this requires the spine to decide hosting (that is correctly Q12) or bundling (correctly Q9). It requires three or four sentences — or one new AD — fixing: where the shell artifact is produced, what header/cache posture it carries, that `crypto.subtle` implies a secure context, and that `history`/`storage`/`crypto` are injected ports so the whole envelope is testable under `node --test` with no new dependency. As written, the spine fixes seven seams inside the shell and leaves the seam *between the shell and the deployment* entirely open — which is where the only currently-running pipeline actually lives.

**F-18 — Error/warning presentation across the new surface is undecided and undeferred. Severity: low.** The reducer emits `warning: 'company-unavailable' | 'model-unavailable' | 'news-unavailable'` ([exploration-state.mjs:126,133,136](../../../../../src/domain/exploration-state.mjs#L126-L136); vocabulary at [exploration.mjs:233](../../../../../src/contracts/exploration.mjs#L233)) and `LocalSearch` emits `status: 'unavailable'` ([local-search.mjs:50](../../../../../src/application/local-search.mjs#L50)). Story 7.1 AC-4 requires the system to "informa indisponibilidade". Two surfaces now carry unavailability signals with no rule about which one Andre sees, and CR-09 ([deferred-work.md:38](../../../../implementation-artifacts/deferred-work.md#L38)) records that `warning` is wiped by the next unrelated intent ([exploration-state.mjs:70](../../../../../src/domain/exploration-state.mjs#L70) `s.warning = null`). The epic that introduces the first consumer of `warning` should at least defer this with a named owner rather than omit it.
